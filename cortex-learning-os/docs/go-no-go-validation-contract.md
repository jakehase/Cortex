# Cortex Learning OS capped go/no-go validation contract

## Reply anchor and objective

Jake approved the bounded recommendation in the replied WhatsApp message on 2026-07-25: run one mechanism test and one private-workspace utility test, require replicated preregistered improvement plus cost/no-regression gates, and keep the feature out of the default path unless both pass.

This is a go/no-go validation of incremental retrieval value. It is not model training, weight learning, a broad mastery test, or approval to enable ordinary-task routing.

## Frozen program shape

The real program must be frozen with `--plan-only` before any program model call.

- Runtime: fresh ephemeral Codex sessions, `gpt-5.6-sol`, low reasoning, read-only sandbox, no tools.
- Acquisition: 3 calls for one seeded synthetic procedure:
  1. baseline without the procedure must fail;
  2. correction with the procedure must pass;
  3. independent retest with the procedure must pass;
  4. all existing promotion gates must promote the scoped lesson.
- Mechanism transfer: 27 identical-item pairs / 54 sessions, promoted synthetic lesson pack versus no pack.
- Private utility: 27 identical-item pairs / 54 sessions over nine low-sensitivity operator-curated workspace corrections, item-matched pack versus no pack.
- Total cap: 111 model calls. No outcome-driven reruns.
- Schedule: randomized pair order, randomized within-pair arm order, and randomized interleaving of the two transfer tracks.

The private fixture stays outside the public Git branch. The frozen private artifact may contain only low-sensitivity operational rules; credentials, tokens, client-identifying facts, financial identifiers, and infrastructure addresses are prohibited.

## Per-track gates

Each track must independently satisfy all of the following:

- at least 24 valid pairs;
- invalid-pair rate no greater than 10%;
- pack accuracy lift at least 20 percentage points;
- pack-only wins exceed no-pack-only wins;
- two-sided exact McNemar p-value no greater than 0.05;
- no more than one no-pack-only pair;
- mean pack input-token overhead no greater than 1,200 tokens;
- maximum retrieval-pack estimate no greater than 900 tokens;
- median pack latency overhead no greater than 10 seconds.

## Program decision

`GO — bounded shadow-integration candidate` requires:

1. acquisition promotion;
2. mechanism track pass;
3. utility track pass;
4. every effect, no-regression, token, and latency gate above.

A GO result allows only a bounded shadow-mode candidate. It does not approve default routing or a durability claim.

Any other terminal result is:

`NO-GO — preserve as verified memory/retrieval toolkit`.

A no-go is a valid completed result, not an implementation failure. It must not be retried based on outcomes.

## Evidence requirements

Preserve:

- frozen program and input digests;
- acquisition attempts, verifiers, mistake, candidate, promotion proof, and trusted lesson;
- every provider event, prompt, answer, usage record, score, validity decision, and retrieval pack;
- per-track paired analyses and whole-program decision;
- campaign state, blocker state, and SHA-256 manifest;
- an independently checksummed return bundle verified on the control plane.

Mechanical completion, each track pass, program pass, durability, and default-path approval remain separate truth layers.
