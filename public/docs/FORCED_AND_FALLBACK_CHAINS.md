# Forced and fallback chains

## Core idea

Cortex novelty is not only in individual levels.
It is also in the explicit chains that combine them.

## Types of chains

### Forced chains
These are patterns where a class of task explicitly pushes the system into a known sequence.

Examples:
- research chain
- creativity-governor chain
- coding/design chain
- L9-heavy architecture chain

### Fallback chains
These are patterns where the system degrades in an explicit direction rather than pretending nothing changed.

Examples:
- fallback when a preferred capability is degraded
- validator-first or council/synthesis fallback patterns
- explicit routing fallback when a canonical path is unavailable

## Why this matters

A flat agent loop treats fallback as incidental.
A more deliberate architecture treats fallback as part of the system design.

## Distinctive claim

The interesting part is not merely “a fallback exists.”
The interesting part is that chain behavior itself is part of the architecture and can be documented, audited, and improved.
