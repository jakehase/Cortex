# Why Cortex is not just an agent framework

## Short version

Because Cortex is trying to be more than:
- a tool-calling loop
- a prompt wrapper
- a generic orchestration harness

## Agent frameworks usually provide

- tool use
- workflows/graphs
- memory hooks
- model integrations
- maybe browser or sandbox support

Those are useful, but common.

## Cortex is aiming at more

- cognitive routing, not just workflow routing
- layered research behavior, not just search calls
- epistemic memory behavior, not just retrieval
- capability reality-checking, not just feature lists
- explicit failure semantics, not just graceful-looking fallbacks
- control-plane/self-audit concepts, not just execution

## Important nuance

This does not mean Cortex rejects agent frameworks.
It means the architectural ambition is different.

The goal is a reasoning-and-execution stack with:
- modes of cognition
- evidence-aware memory
- explicit validation and fallback behavior
- awareness of implementation reality

## Distinctive claim

If Cortex succeeds, it should feel less like a single agent loop and more like a layered cognitive system operating through a runtime.
