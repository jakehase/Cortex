# cortex-memory-bridge

Workspace memory plugin routing OpenClaw `memory_search` into Cortex HTTP search.

Status: candidate implementation; this document does not assert deployment or live activation.

Notes:
- `memory_search` maps to Cortex `/knowledge/search`.
- `memory_search.filters` exposes the typed source/path/type/tag/fact/claim/project/privacy/status/as-of/as-known-at filter contract. Cortex applies supported metadata and temporal predicates before semantic ranking and rechecks them after retrieval.
- Query-time routing now classifies searches into `fast`, `reconcile`, or `investigate` modes.
- The bridge performs conflict-aware reranking: recency, explicitness, source quality, corroboration, and stale/superseded penalties are folded into the final score.
- `memory_search` responses now include `memoryMode`, `queryType`, `resolvedFacts`, and `conflicts` metadata to support higher-trust memory answers.
- When memory is clean-but-empty after noise suppression, the response includes a `fallback` hint telling the caller to use workspace/filesystem or live tools instead of over-trusting empty memory.
- `memory_get` reads only exact `cortex:<record-id>` paths through `/librarian/record`, under the same signed principal as `memory_search`, and validates the returned record/window before exposing text.
- Historical/completion-style queries are allowed to surface completion chatter more naturally; short vague queries are biased toward curated memory.
- Every request sends one complete tenant/workspace/agent/user/channel/session principal. Configure `scopeCredentialId` and its credential-specific `scopeHmacSecret`; plugin registration fails before tools, hooks, or spool replay start when either is missing. The write token is deliberately not accepted as a scope-signing key. Cortex rejects incomplete principals and credentials whose allowed-scope list does not contain the exact requested principal. Unsigned requests require the explicit `allowUnsignedLocalDevelopment: true` escape hatch, which defaults off and is restricted to the default `cortex-local/default` scope.
- `memory_search` binds identity from OpenClaw's trusted tool-factory context, never from model-controlled tool arguments. A callback session is mandatory; missing fixed agent/user/channel fields may use plugin configuration. When `ownerSenderId` is configured, an explicit foreign or conflicting sender is denied before HTTP. A truly session-only callback uses the fixed owner binding, but a no-sender callback carrying a foreign `userId` is rejected rather than upgraded to owner scope.
- Lifecycle callbacks must provide a trusted session identity. Because OpenClaw lifecycle hooks do not always repeat fixed principal fields, configured agent/user/channel values may fill only those fixed dimensions; the complete scope is still HMAC-signed and checked against the credential allow-list before Cortex accepts it. Owner-bound lifecycle fallback applies the same no-sender/foreign-user rejection as search and read.
- Codec continuity is enabled by default and requires `sessionIdentityHmacSecret` shared with `cortex-route-gate`, producing one canonical opaque session key on writes and live reads. Explicitly provision one secret outside the repository and configure its exact value in both plugin entries; neither plugin has a built-in secret. Configure the same tenant/workspace and credential-specific `scopeCredentialId`/`scopeHmacSecret` in the route gate so orchestration sends the same complete signed principal as memory access. Missing or blank session-secret values fail plugin registration before lifecycle hooks and spool replay start. Assurance-gated write-through remains separately configurable and counts output as stored only after Cortex confirms the scoped durable write.
- Disabling both persistence modes is explicit: lifecycle persistence reports failure and retains buffered output instead of acknowledging or deleting it.
- Lifecycle hooks return a bounded structured outcome (`persisted`, policy `skipped`, or `pending_retry`) with per-writer status and a hashed key. Subagent failures remain spooled and visible without aborting the subagent callback; `agent_end` retries them and throws a structured pending error if persistence still fails.
- When lifecycle persistence is enabled, bursts use a bounded backpressure queue and an atomic, permission-restricted spool under `stateDir`. Hash-only metadata remains visible on disk, while the bounded replay payload and any server assurance receipt are sealed separately with AES-256-GCM. Ciphertext is authenticated against the complete principal namespace, persistence key, creation time, and plaintext SHA-256; receipt ciphertext is additionally bound to the replay-payload hash. The key is derived from `lifecycleEncryptionKey` when supplied, otherwise from the already provisioned session/scope authentication secret for backward-compatible deployments; no key or plaintext receipt is stored in the spool. Version-4 records replay automatically after restart and retain the same assurance receipt until Cortex proves an idempotent commit. Legacy hash-only records remain callback-gated rather than being misrepresented as replayable.
- `memory_delete_principal` requires the exact destructive confirmation token, creates the server deletion fence first, deletes principal-scoped Cortex projections/ledgers/outbox and owner-index receipt state, then purges pre-fence encrypted local spool records and volatile caches. It deliberately preserves owner source files; source-file deletion is a separate explicit action and a later explicit reindex can rehydrate them.
- Runtime status is explicitly unverified until probed. A bare HTTP 200 with an empty result set is not health evidence; explicit backend availability proves reachability only, and degraded lexical results are not labeled semantic verification.
